# The CopyMonster mask follows the live model catalog

**Decision.** `dsh-host-model-mask` no longer accepts a configured primary provider/model, and `copy-monster-default` is not a selectable model. The alias resolves its real route from the live `llm` registry on every turn: the deployment default from `agentDefaultModel` when it matches an advertised model, otherwise the first advertised model, with every other advertised model forming the ordered fallback chain bounded by `fallbackPolicy.maxAttempts`.

**Why.** The pinned route made the mask a second model configuration: an operator who added a provider in Settings > Models still saw tenant turns fail until someone also edited `cordis.patch.yml`. With two sources of truth, a new provider looked configured while serving nothing. The alias also appeared in pickers as if it carried a provider and key, which it never did.

**Consequences.** Settings > Models is the only place a route is chosen, so a provider added there serves tenants on the next request. Reading the catalog fails a turn only when no provider advertises any model; the sentinel route `none/none` then surfaces the runtime's `NO_ADAPTER` error instead of silently redirecting. A provider whose catalog lookup throws is skipped rather than removing the remaining routes. Administrators keep the real catalog in the picker and read the resolved route through the read-only `session/modelMaskStatus` remote (operator-only, since it names real providers), which backs the Admin tab's "Model in use" card. Failover still never crosses an emitted chunk.
